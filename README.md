# 業務効率化タスク・プロジェクト管理ツール

個人のスケジュールやチームのプロジェクト進行を可視化する、業務効率化タスク・プロジェクト管理ツールです。プロジェクトの見える化に加え、ヒト・コト・モノを管理できます。

## 概要

IT・製造などプロジェクト型の業種においてタスクの登録・進捗管理・ガントチャート表示・チーム管理などをワンストップで行えるWebアプリケーションです。

## 主な機能

- **ユーザー管理**
  - メールアドレスによるログイン・サインアップ（Spring Securityによる認証）
  - ロール制御（管理者 / 一般メンバー / ゲスト）
- **タスク管理**
  - タスクの作成・編集・削除（担当者、優先度、期限、工数の見積もりと実績）
  - 繰り返しタスクの自動生成（`@Scheduled`によるルーティン業務対応）
  - ドラッグ＆ドロップ対応のカンバンボード
- **プロジェクト管理**
  - プロジェクト作成・メンバー管理（同一チーム内メンバーの追加/削除）
  - ガントチャートによるスケジュール可視化
  - マイルストーン管理（達成状況のステータス管理）
  - プロジェクト別・メンバー別の工数集計レポート
- **管理者機能**
  - ユーザー・チーム・部署の管理
  - システム全体のダッシュボード（ユーザー数、稼働プロジェクト数など）
- **ゲスト機能**
  - 閲覧専用のタスク一覧・ガントチャート
- **外部連携**
  - Slack / Teams / Google Calendarとの連携設定画面

## セットアップ

### 前提条件

- Java 17以上
- PostgreSQL 17
- Gradle

### 環境変数

```
APP_ENCRYPTION_SECRET_KEY=<暗号化用シークレットキー>
DB_PASSWORD=<データベースパスワード>
```

### 起動手順

#### 1. リポジトリをクローン

```bash
git clone git@github.com:KDGT2403731/task_management_tool.git
cd task_management_tool
```

#### 2. データベースを準備

PostgreSQLを起動し、アプリ用のデータベースを作成しておきます。

```bash
createdb taskmanagementtool
```

（DB名・接続情報は `application.properties` の設定に合わせてください）

#### 3. 環境変数を設定（任意）

`DB_PASSWORD` は各自の環境のDBパスワードに合わせて設定してください。
`APP_ENCRYPTION_SECRET_KEY` は未設定でも開発用のデフォルト値で起動しますが、本番運用時は必ず独自の値を設定してください。

```bash
export DB_PASSWORD=<データベースパスワード>
export APP_ENCRYPTION_SECRET_KEY=<暗号化用シークレットキー>
```

#### 4. アプリケーションを起動

開発環境（`dev`プロファイル）で起動すると、`schema.sql` / `data.sql` によりテーブル作成とシードデータ投入が自動で行われます。

```bash
./gradlew bootRun --args='--spring.profiles.active=dev'
```

`dev`プロファイルを指定しない場合、スキーマの自動初期化は行われません（`spring.sql.init.mode=never`）。既存データを保持したまま本番相当の環境で起動する場合はこちらを使用してください。

```bash
./gradlew bootRun
```

#### 5. アクセス

起動後、ブラウザで以下にアクセスします。

```
http://localhost:8080
```

## 使い方

サインアップからタスク管理までの一連の流れをまとめます。

### 1. サインアップしてログインする

`/signup` からメールアドレスと名前・パスワードを登録します。サインアップしたユーザーは自動的に「一般メンバー」として登録され、同時に自分専用のチーム（`{名前}のチーム`）が作成されます。チームに所属していないとプロジェクトを作成できないため、通常のサインアップだけで最初のプロジェクト作成に必要な準備は整います。

管理者（ADMIN）・ゲスト（GUEST）権限のユーザーは、サインアップ画面からは作成されません。管理者が `/admin/users` からロールを変更することで昇格・変更します。

### 2. プロジェクトを作る

ログイン後、`/projects` からプロジェクトを新規作成します。作成したユーザーがそのプロジェクトのオーナー（owner）になります。

### 3. チームメンバーをプロジェクトに招待する

プロジェクトを作成した直後は、オーナー本人しかそのプロジェクトのメンバーになっていません。同じチームの他メンバーにタスクを見せたり担当させたりするには、プロジェクト詳細画面のメンバー欄から「同じチームに所属するユーザー」を追加する必要があります。これを行わないと、チームメンバーがタスクが見えないので注意してください。

### 4. タスクを登録・管理する

プロジェクト内の「タスク一覧」からタスクを作成します。担当者・優先度・開始日/期限・見積工数を設定でき、一覧画面はドラッグ＆ドロップ対応のカンバンボードとしても操作できます。

タスク詳細画面では以下も設定できます。

- **前提タスク / 後続タスクの依存関係**：「このタスクの前に終わらせておくべきタスク」を前提タスク、「このタスクの後に始まる／終わるタスク」を後続タスクとしてそれぞれ登録できます。
- **繰り返しタスク**：頻度（毎日/毎週/毎月など）か、任意のCron式を指定して、定期的に同じタスクを自動生成できます。

### 5. 進捗を可視化する

- **ガントチャート**（`/projects/:projectId/tasks/gantt`）：タスクの期間と依存関係を時系列で確認できます。
- **分析レポート**（`/projects/:projectId/reports`）：メンバーごとの見積工数と実績工数の差を確認できます。

### 6. デモアカウント

`dev`プロファイルで起動した場合、`data.sql`により以下のアカウントがシード投入されます。ロールごとの画面の違いを試したいときはそのままログインできます。

| 名前 | メールアドレス | パスワード | ロール |
| --- | --- | --- | --- |
| 田中博司 | hirotanaka@gmail.com | tanahiro | 管理者（ADMIN） |
| 鈴木太郎 | tarosuzuki@gmail.com | suzukit | 一般メンバー（MEMBER） |
| 山田花子 | hanakoyama@gmail.com | hanako12 | ゲスト（GUEST） |

※ 鈴木太郎（MEMBER）はシード投入時点ではチームに所属していないため、プロジェクトを作成する前に管理者アカウントでチームへの割り当てを行うか、一度ログアウトして通常のサインアップでアカウントを作り直してください。

### 7. 管理者・ゲストとして使う場合

- **管理者（ADMIN）**：`/admin/dashboard` からユーザー数・稼働プロジェクト数などシステム全体の状況を確認し、`/admin/users`・`/admin/teams` でユーザーのロール変更やチーム管理を行います。
- **ゲスト（GUEST）**：`/guest/dashboard` から、共有されたタスクの一覧・ガントチャートを閲覧専用で確認できます（作成・編集はできません）。

## アーキテクチャ

- Controller / Service / Repository の3層構造
- Controllerは薄く保ち、ビジネスロジックは`@Transactional`なServiceに集約
- コンストラクタインジェクションを採用
- ID基準の`equals`/`hashCode`実装により、双方向関連（User⇔Project、Team⇔TeamMemberなど）での循環参照を回避
